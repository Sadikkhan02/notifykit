# Troubleshooting & Production Operations

This guide provides practical solutions for diagnosing and resolving common operational issues when deploying **NotifyKit** to staging and production environments.

---

## 1. Redis Connectivity & Queue Errors

### Error: `RedisUnavailableError` or `ECONNREFUSED 127.0.0.1:6379`
- **Cause:** The application cannot establish a TCP connection to the Redis server specified in `REDIS_URL`.
- **Diagnostics:**
  1. Verify Redis is running: `redis-cli -u $REDIS_URL ping` (expect `PONG`).
  2. If running Docker: Verify port mapping `docker ps` shows `0.0.0.0:6379->6379/tcp`.
  3. If connecting to cloud Redis (Upstash, AWS ElastiCache, Redis Enterprise): Ensure TLS prefix is used if required (`rediss://...` with double `s`).

### Warning: Redis Eviction Policy Warning
- **Cause:** Redis server is configured with an aggressive eviction policy (such as `allkeys-lru` or `volatile-lru`).
- **Impact:** Redis might evict BullMQ queue metadata, waiting jobs, or delayed retry markers when memory is pressured.
- **Solution:** Configure your Redis instance with `maxmemory-policy noeviction` or `volatile-ttl`. Ensure sufficient memory allocation.

### Process Hangs on Exit / Unclosed Handles
- **Cause:** Node.js event loop remains open because BullMQ queue workers or `ioredis` connection sockets are still active.
- **Solution:** Always trigger a graceful teardown sequence before terminating the process:
  ```typescript
  import { resetDefaultRegistry, closeRedisConnection } from 'notifykit';

  // 1. Drain workers
  await notifier.stopWorker();
  // 2. Close queue producer instances
  await resetDefaultRegistry();
  // 3. Terminate shared Redis client
  await closeRedisConnection();
  ```

## 2. Email Delivery Issues (Nodemailer)

### Error: `535 5.7.8 Username and Password not accepted`
- **Cause:** SMTP credentials rejected by provider.
- **Solution:**
  - If using Gmail: Standard Google account passwords cannot be used. Generate a dedicated 16-character **Google App Password** in Google Account Security.
  - If using Mailgun / SendGrid: Verify whether the username should be `apikey` and the password your full API token.

### Error: `ETIMEDOUT` or `Greeting never received`
- **Cause:** Port and SSL encryption mismatch.
- **Solution:**
  - Port **465** requires `secure: true` (direct TLS/SSL socket).
  - Port **587** requires `secure: false` (starts plaintext and upgrades via STARTTLS).
  - Verify your hosting provider or cloud VPC does not block outbound port 25 or 587.

## 3. SMS Issues (Twilio & MSG91)

### Error: Twilio `21211 Invalid 'To' Phone Number`
- **Cause:** The recipient phone number is not formatted in valid international **E.164** format.
- **Solution:** Always prefix country codes with `+`. Example: `+15555550199` (US), `+919876543210` (India), `+447911123456` (UK). NotifyKit marks this error as `retryable: false` and routes it directly to the DLQ.

### Error: Twilio `30034 US A2P 10DLC Unregistered`
- **Cause:** You are sending SMS to a US number from an unregistered 10-digit local number.
- **Solution:** Register your Brand and Campaign in the Twilio Trust Hub, or use a verified Toll-Free number / Short Code.

### Error: MSG91 `Invalid Flow ID` or `Template mismatch`
- **Cause:** The `flowId` in configuration does not match an approved DLT Template ID, or required template variable names differ.
- **Solution:** Log in to MSG91 Flow builder. Ensure every placeholder in the approved DLT template matches the keys supplied in `data: { ... }`.

## 4. Push Notification Issues (FCM)

### Error: `messaging/registration-token-not-registered`
- **Cause:** The user uninstalled your mobile app, revoked notification permissions, or the device token expired.
- **Classification:** **Expected behavior.** NotifyKit classifies this error as `retryable: false` and transfers the job to the Dead-Letter Queue (DLQ).
- **Recommended Action:** Consume DLQ events or listen to worker failure events to prune stale device tokens from your user database.

### Error: `messaging/mismatched-credential`
- **Cause:** The target device token was generated by a Firebase project that differs from the service account key configured in NotifyKit.
- **Solution:** Ensure your client app (`google-services.json` or `GoogleService-Info.plist`) and NotifyKit backend share the exact same Firebase Project ID.

## 5. Investigating Failed Jobs via the Dead-Letter Queue (DLQ)

When a job fails terminally or exhausts its 5 retry attempts, it is routed to `bull:notifykit:dlq`.

You can inspect failed jobs directly using Redis CLI or BullMQ:

```bash
# View all terminal failures in the DLQ
redis-cli KEYS "bull:notifykit:dlq:*"

# Inspect the payload and failure reason of a specific job
redis-cli HGETALL "bull:notifykit:dlq:<job-id>"
```

### Key Fields in a DLQ Record
- `terminalReason`: Detailed description of why retries were aborted (e.g. `NON_RETRYABLE_ERROR: Twilio Error 21211`).
- `traceId`: The UUIDv7 correlation trace ID.
- `attemptsMade`: Number of attempts before failure.
- `failedReason`: Raw sanitized error stack.

## 6. Enabling Debug Telemetry

To trace an issue through the entire lifecycle, set `logLevel: 'debug'` in `createNotifier`:

```typescript
const notifier = createNotifier({
  logLevel: 'debug',
  // ...
});
```

All logs will output structured JSON correlated with `traceId`:

```json
{"level":20,"time":1700000000000,"traceId":"018c1b9a-4e20-7f32-8e10-918237465abc","jobId":"018c1b9a-4e20-7f32-8e10-918237465abc","channel":"email","provider":"nodemailer","msg":"Dispatching notification job to adapter"}
```
